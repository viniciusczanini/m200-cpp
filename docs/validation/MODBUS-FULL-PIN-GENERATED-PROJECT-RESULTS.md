## Exact source and native representation

The recorded public command is `python3 -m m200 compile SOURCE --template TEMPLATE
-o OUTPUT`. The frozen bundle under
`output/diagnostics/modbus-generated-full-pin-candidates-2026-11-06/` contains
the separate READ, WRITE and WR sources, exact authentic full-pin templates,
CLI logs and build outputs. The manifest retains each verbatim argv and working
directory. Generation was not rerun for this report, and no XML was hand-edited.

Each source includes `<plc.hpp>` and uses its corresponding exact constructor:

```cpp
// Separate sources:
plc::ReadVar remote{0,plc::Link::Serial1,1,100,
    plc::Object::DiscreteInputs,17,17,200};
plc::WriteVar remote{0,plc::Link::Serial1,1,100,
    plc::Object::Coils,73,17,240};
plc::WriteReadVar remote{0,plc::Link::Serial1,1,100,
    17,2,300,41,3,400};
```

All three call `remote.update(plc::read_m(10), plc::read_m(13))`, then store
DONE/BUSY/ABORTED/ERROR to `%M14/%M15/%M16/%M17` in that order. The compiler
snapshots Execute and Abort into `%M500/%M501` before the block. The source uses
memory operands and has no physical I/Q operands or transport callback; READ I
and WRITE Q identify remote Modbus object spaces.

Each product has **seven canonical rungs / eighteen instructions**, represented
in SMBP as **three native rungs / nineteen instructions**: two snapshot rungs
and one fifteen-line full-pin block. Graph counts are **11 / 11 / 27**, or 49
entities. These are representation counts, not scans or additional GUI tests.
